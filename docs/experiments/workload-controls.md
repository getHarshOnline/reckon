# KeyDoor and Bandit memory controls

This diagnostic checks the workload limits identified by the [first retention pilot](../09-Tasks-Benchmarks.md#the-first-measured-retention-pilot-exposes-workload-limits) on the current repaired source. It keeps KeyDoor's single-cue path and Bandit's task-directed indicator replacements. It does not redesign either task, repeat the completed Tutor confirmation or test a general policy advantage.

## Fixed comparison

Use the [configuration](../../notebooks/experiments/workload_controls.json): the unchanged pilot environments, three carried-memory episodes per seed, utility learning enabled, and one or two slots without a byte cap. Bandit has two arms, two modes, a 25-pull switch interval, indicator probability 0.1 and the existing reward noise standard deviation 0.1; each episode still has 200 pulls. KeyDoor uses its repaired fixed grid. Compare no memory, full capacity, FIFO, LRU, seeded random, explicit importance, learned utility, Diversity and measured retention. No memory and full capacity run once per seed. The other seven policies run at both budgets, giving 32 task-policy-budget rows and 1,536 main episodes across the 16 fresh seeds 30,000–30,015. Seed 29,999 is reserved for checking the runner and excluded from the result.

At each measured-policy pruning decision, use four fixed paired trials per retained record, one fresh task episode per arm, FIFO as the reference policy, carried starting memory and utility learning. Use the existing permutation test with 256 requested resamples (four pairs allow all 16 sign combinations), Bonferroni correction across candidates at that decision, alpha 0.05 and the existing 0.05 probe threshold. Disable adaptive sampling and early stopping. This small probe is diagnostic; no power or policy-adoption claim follows from its significance output.

For task index `t` in configuration order and outer seed index `i`, start probe seeds at `1,000,000,000 + (16 * t + i) * 100,000`. Each decision advances by four, as the existing runner specifies. The main task can write at most 600 times, so a task/outer-seed block cannot exhaust its reservation. Both budgets share the assigned stream. The runner-check seed uses its own block starting at 2,000,000,000. These streams do not overlap the main seeds, the older pilot or the Tutor confirmation.

## What the controls can establish

KeyDoor stores one cue and retrieves that episode's ID before another write. The manager makes room by removing existing records before admitting the new one, so a positive slot budget can retain the currently needed cue regardless of how it ranks older cues. Bandit similarly retrieves its current indicator by ID, writes a replacement before its next decision, and explicitly removes the old indicator or removes it at a tracked mode switch. Its controller is told that a switch occurred; this is not a test of discovering the switch from rewards alone. Report these task-directed removals separately from capacity-driven policy removals.

Both tasks start fresh probes with empty task-local ID variables. Copied historical records can therefore remain unread even though the live task benefits from its new cue. Read the saved initial-record read counts and paired outcomes together: an unused intervention target is a limit of this fresh-task probe, not evidence that a cue is useless when the live controller needs it. All measured estimates, including unexpected nonzero or adverse ones, remain in the result.

Report each policy's seed mean, sample standard deviation, paired differences from full memory and from learned utility, writes, sampled store peaks, task removals, policy removals, probe episodes and inclusive/probe elapsed time. Main seed outcomes are the unit of description. Do not add seeds, change the workload or tune a policy after inspecting results. Identical observed outcomes support the stated control behavior under these conditions; they are not a powered equivalence result or evidence about a workload with competing useful records. No Beta-posterior arm is added: there is no separately specified and implemented posterior retention policy to compare here.
