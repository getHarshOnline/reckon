# Contributing to Reckon

Thank you for your interest in contributing to Reckon, a laboratory for causal records under resource budgets.

## How to Contribute

### Reporting Issues

- Use GitHub Issues to report bugs or suggest features
- Search existing issues before creating a new one
- Provide clear reproduction steps for bugs

### Pull Requests

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-feature`)
3. Make your changes
4. Add tests if applicable
5. Ensure all tests pass
6. Submit a pull request

### Code Style

- Follow PEP 8 for Python code
- Use type hints where appropriate
- Document public APIs with docstrings

### Documentation

- Update relevant docs when changing functionality
- Follow the existing documentation structure in `docs/`

### Areas of Contribution

- **Core Framework**: Improvements to the mathematical foundations
- **Memory Manager**: New retention policies, scoring mechanisms
- **Benchmarks**: New tasks that demonstrate selective memory benefits
- **Debugger**: Visualization improvements, new diagnostic views
- **Tests**: Expanding test coverage

## Code of Conduct

Be respectful and constructive in all interactions. We're building something together.

## Questions?

Open a discussion or issue if you need guidance on contributing.
